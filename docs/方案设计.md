## 2026-08-31 方案：RAscore 条件化 CFG

### 技术方案概述

在现有 Stage 3 固定拓扑、联合化学与坐标扩散的基础上，增加 RAscore 条件变量。训练时随机丢弃该条件，让同一个去噪器同时学习有条件和无条件预测；采样时分别得到 conditional/unconditional 预测，再用 CFG 公式合并坐标噪声、原子类别 logits 和固定边键类别 logits。RAscore 本身只在离线标注和生成结果重排阶段调用，不放进每一个扩散步，也不对 RDKit/RAscore 做反向传播。

### 技术选型

| 类别 | 选择 | 理由 |
|------|------|------|
| 条件形式 | 连续 RAscore 加条件缺失 mask | 保留原始分数信息，并能识别失败或缺失的外部评分 |
| CFG 训练 | 条件丢弃，默认概率 0.1 | 不增加第二个模型，训练目标和现有联合扩散兼容 |
| CFG 采样 | `u + scale * (c - u)` | 同时作用于坐标噪声和两个化学类别输出 |
| RAscore 调用 | 离线缓存 + 采样后重排 | 避免训练和扩散反向过程被外部模型/SMILES 转换拖慢 |
| 训练数据 | 保留原始 JSONL，增加版本化 sidecar | 可以复用已有 1000 条库，也方便扩展到 1500 万条 |

### 架构设计

```text
canonical_isomeric_smiles
        |
        v
RAscoreProvider ----> rascore_cache.jsonl
        |                         |
        +-------------------------v
  TrainingRecord.conditioning = {rascore, mask, scorer_version}
        |
        v
  RAscoreConditionEncoder --+
                             +--> timestep/condition embedding --> denoiser
  CFG condition dropout ----+

  sampling: prediction_uncond + scale * (prediction_cond - prediction_uncond)
        |
        +--> fixed-topology reverse diffusion
        +--> reconstruct molecule --> RAscore --> rerank/filter
```

### 模块划分

| 模块 | 职责 | 依赖 |
|------|------|------|
| `RAscoreProvider` | 调用指定 RAscore 实现并返回分数、版本和状态 | 用户提供的 RAscore 包/模型 |
| 离线评分脚本 | 按 canonical SMILES 评分、缓存、统计失败项 | `RAscoreProvider`、现有 JSONL/SQLite |
| 数据条件适配 | 将 RAscore 写入训练记录并在 batch 中生成张量 | `TrainingRecord`、collate |
| 条件编码器 | 将标量分数和 mask 编码到去噪器时间条件 | Stage 3 denoiser |
| CFG 组合器 | 合并 conditional/unconditional 的三类预测 | joint sampler |
| 结果重排器 | 对采样结果重新计算 RAscore，记录有效率和分数分布 | 分子重建、RAscore |

### 接口设计

#### 离线评分接口

```python
class RAScoreProvider(Protocol):
    @property
    def version(self) -> str: ...

    def score(self, canonical_isomeric_smiles: str) -> float: ...
```

缓存记录至少包含 `molecule_key`、`canonical_isomeric_smiles`、`ra_score`、`status`、`scorer_version` 和错误信息。评分失败不能默认为高分；训练阶段应由 `mask=false` 标识并按配置跳过、降权或拒绝，默认采用拒绝并输出失败报告。

#### 训练记录接口

在 `TrainingRecord` 中增加显式条件字段，而不是把模型输入藏在自由文本 metadata 中：

```python
conditioning = {
    "rascore": float,
    "rascore_mask": bool,
    "rascore_version": str,
}
```

batch 后得到 `[B, 1]` 的分数张量和 `[B, 1]` 的条件 mask。原有 `edge_index`、`atom_mask`、`edge_mask`、atom/bond labels 不变；RAscore 不作为干净化学标签写入 feature manifest，避免条件和预测目标混淆。

#### CFG 配置接口

建议新增配置段：

```yaml
guidance:
  enabled: true
  type: classifier_free
  condition: rascore
  train_condition_dropout: 0.1
  sampling_scale: 1.5
  apply_to: [coordinate, atom_logits, bond_logits]
  rerank:
    enabled: true
    num_candidates: 8
    invalid_score: 0.0
```

`sampling_scale=0` 应等价于无条件分支，`sampling_scale=1` 为普通条件预测。正式训练前需要对 `[0, 1, 1.5, 2, 3]` 做小规模扫描，不把大 guidance scale 直接当成更高质量的保证。

### 训练流程

1. 从现有记录的 canonical isomeric SMILES 生成一次 RAscore sidecar，并记录 scorer 版本、模型指纹、成功率和分数分布。
2. 将分数归一化到 RAscore 实际定义的范围；不在代码中硬编码范围，先由 provider 校验。若分布严重偏斜，保留连续分数，同时增加分位数 bucket 作为备选实验。
3. 每个 batch 以 `train_condition_dropout` 概率将 RAscore 替换为 null condition。条件丢弃只影响条件输入，不修改 atom/bond/coordinate 目标。
4. 条件编码与 timestep embedding 融合后进入现有等变去噪器。坐标损失、atom 分类损失、bond 分类损失及固定拓扑 mask 逻辑保持不变。
5. checkpoint 保存 CFG 配置、RAscore scorer 版本、缓存指纹和条件归一化参数；恢复训练时做一致性校验。

### 采样与重排

每个反向扩散步使用同一个 noisy state 分别运行无条件和有条件分支：

```text
coordinate_noise_cfg = u_coord + s * (c_coord - u_coord)
atom_logits_cfg      = u_atom  + s * (c_atom  - u_atom)
bond_logits_cfg      = u_bond  + s * (c_bond  - u_bond)
```

之后仍使用原有固定拓扑 reverse step；不新增边、不改变 `edge_index`，也不引入 `NO_BOND`。采样完成后重建分子并再次计算 RAscore，用于候选排序和审计。CFG 只表达“向目标分数分布靠近”，不能保证每个生成分子一定达到目标分数；若需要更强约束，使用候选重排或后续训练可微 surrogate，而不是在扩散循环中直接调用不可微的 RAscore。

### 验证计划

| 阶段 | 验证内容 | 通过标准 |
|------|----------|----------|
| 单元测试 | 条件丢弃、条件 mask、CFG 线性组合、缺失分数处理 | 固定 seed 可复现，shape/device/mask 全部正确 |
| 1000 条数据 | 离线评分、物化、joint training、joint sampling | 全链路完成，失败项可追溯，无 RAscore 在线调用 |
| 消融实验 | 无 CFG、CFG scale 0/1/1.5/2/3 | 同时报告坐标误差、atom/bond 指标、化学有效率和 RAscore 分布 |
| 稳定性测试 | 多个 seed、不同分子大小和元素类别 | 不出现某一大小区间或稀有元素的明显退化 |
| 大规模前置 | 100k、1M 子集逐级扩展 | 吞吐、显存、缓存命中率和 checkpoint 恢复稳定 |

数据划分继续按稳定分子身份做确定性哈希；多环分子的多个 ring-system 记录必须共享同一 `split_group`，但训练记录 ID 保持唯一。不能把当前抽样优先级顺序当作 scaffold/source 分组。

### 风险与待确认项

1. 需要确认实际使用的 RAscore 包、模型文件或命令行入口，以及其返回值范围和版本。方案不默认自动安装外部依赖。
2. 如果 RAscore 只能接受完整有效 SMILES，采样后评分必须先经过分子重建和有效性检查；无效结果按配置记为失败，不能伪造分数。
3. RAscore 条件化会增加每次采样至少一次额外的去噪器前向；可在后续通过 batch 拼接 conditional/unconditional 两路减少开销。
4. 1000 条数据只用于验证接口和方向，不能据此确定最终 guidance scale 或模型容量。

### 实施顺序

1. 确认 RAscore 运行入口、版本和目标分数语义。
2. 实现离线评分缓存与数据条件字段，先在 1000 条库上生成审计报告。
3. 实现条件编码、训练条件 dropout 和 checkpoint contract。
4. 实现联合采样 CFG、结果重排和配置解析。
5. 增加单元/集成测试，运行 1000 条训练与采样 smoke test。
6. 根据消融结果再决定是否加入 surrogate guidance 或扩大候选重排数量。
