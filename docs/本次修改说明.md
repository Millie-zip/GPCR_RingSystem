## 二、已完成的代码修复

### N1：坐标模式推理结果可以正常保存

原代码在采样完成后，只要 state 中有原子和键标签，就无条件读取 `chemical_vocabulary`。默认坐标模式配置没有该字段，因此最终 JSON 保存失败。

现在坐标模式使用持久化数据的固定词表解释输入标签；联合扩散继续使用配置中的化学词表。原子、键 ID 和原有 JSON 字段保留。新增完整调用测试，实际执行小型训练、保存 checkpoint、加载、采样和结果写出。

主要文件：[training/inference.py](../src/gpcr_ringgen/training/inference.py)、[test_record_inference.py](../tests/integration/test_record_inference.py)。

### N2：统一元素词表及输入转换

固定化学 ID 统一存放于 `gpcr_ringgen.vocabulary`，由 core、data 和离线 3D 资产构建器引用。原 9 类 ID 保持不变，追加元素仍为 `H=9`、`B=10`、`Si=11`，键类型仍为 4 类。默认坐标模型的原子 embedding 扩为 12 类；词表模块和离线资产构建器可在不导入 PyTorch 的情况下使用。

标准 JSON 推理先解析实际模型和扩散配置，再转换类别名称及检查数字 ID。联合模式使用配置中的类别顺序；坐标模式使用与实际 embedding 大小一致的固定词表前缀。回归测试覆盖 H/B/Si 的训练与两条推理入口、非默认词表顺序、越界拒绝，以及旧 9 类 checkpoint 的兼容路径。

主要文件：[vocabulary.py](../src/gpcr_ringgen/vocabulary.py)、[core/vocab.py](../src/gpcr_ringgen/core/vocab.py)、[data/vocabulary.py](../src/gpcr_ringgen/data/vocabulary.py)、[data/stage3_inference.py](../src/gpcr_ringgen/data/stage3_inference.py)、[pipeline/stage3_inference.py](../src/gpcr_ringgen/pipeline/stage3_inference.py)、[build_training_assets.py](../src/gpcr_ringgen/preprocessing/diffusion_dataset/build_training_assets.py)。

### N3：checkpoint 同时校验张量和语义

生成模型与独立 RARewardModel 的 checkpoint 升为 `checkpoint_version: 2`。共享校验模块保存并比较标准化模型参数、完整 diffusion 配置、原子/键词表顺序、完整 feature manifest、Field 通道及定义。训练恢复、记录推理和标准 JSON 推理都在严格加载张量前完成语义比较；生产代码的 `torch.load` 继续使用 `weights_only=True`。

生成模型保存训练 JSONL 的 SHA-256、记录上限、split fraction 和 seed。恢复训练要求这些信息一致；推理可以使用新记录。输入/输出路径、device/dtype、推理 seed 和轨迹保存等运行参数可以调整。新增数据指纹校验没有修复 N7 的旧索引问题，也没有修复 N8 的 best checkpoint 覆盖问题。

奖励 checkpoint 额外保存 teacher 版本、训练数据指纹和标签缓存逻辑行指纹。缓存指纹按 SMILES 排序，包含 score 与 teacher_version，可读取 SQLite WAL 中已提交的数据；混合或缺失 teacher 版本、空缓存会被拒绝。奖励接入需要明确指定预期来源，并核对奖励和生成模型的特征与类别顺序。teacher_version 是标签生成方声明的版本，不能单凭它鉴证外部 teacher 的实现或权重。

这套契约适用于 Stage 3 生成模型与独立 RARewardModel 的 torch checkpoint。历史 pilot ECFP4 LogisticRegression 的 joblib 产物仍需另行复核和重建。

主要文件：[checkpoint_semantics.py](../src/gpcr_ringgen/checkpoint_semantics.py)、[training/trainer.py](../src/gpcr_ringgen/training/trainer.py)、[training/ra_reward.py](../src/gpcr_ringgen/training/ra_reward.py)、[training/ra_reward_training.py](../src/gpcr_ringgen/training/ra_reward_training.py)、[sampling/reward_guidance.py](../src/gpcr_ringgen/sampling/reward_guidance.py)、[test_checkpoint_semantics.py](../tests/integration/test_checkpoint_semantics.py)。

### N4：修正分类逆扩散的概率公式

保持 logits 参数化 `p_theta(z_0|z_t)`，对每个候选 clean 类别的条件后验分别归一化，再按模型预测概率混合。利用均匀转移结构，每个标签以 `O(K)` 的时间和空间计算，无需构造 `K×K` 中间张量。

审查中的两类示例，修复前概率为 `[0.75, 0.25]`，修复后为 `[17/28, 11/28]`，约 `[0.607143, 0.392857]`。独立矩阵枚举测试覆盖 K=2、3、4、12、FP32/FP64、多个时间步、不同 beta 和非均匀预测。`t=0` 仍直接按 clean softmax 采样，mask、padding 和种子传递规则保留。

这项修复没有改变模型结构或训练目标，无需仅因 N4 重新训练。但概率改变后，部分 seed 对应的类别序列会与旧实现不同；当前实现内同 seed 仍可复现。

主要文件：[models/diffusion/chemical.py](../src/gpcr_ringgen/models/diffusion/chemical.py)、[test_categorical_posterior.py](../tests/unit/test_categorical_posterior.py)。公式说明已补充到[Stage 3 详细流程文档](Stage3代码流程详细解析_固定拓扑联合扩散.md)。
